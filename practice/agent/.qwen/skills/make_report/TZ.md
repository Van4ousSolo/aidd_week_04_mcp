# Техническое задание (ТЗ) на разработку генератора отчётов `make_report`

## 1. Цель и назначение
Разработка детерминированного скрипта автоматической генерации сводного аналитического отчёта по задачам TODO в формате Excel (`.xlsx`) для интеграции в качестве навыка (skill) агента Qwen Code / Claude Code.

## 2. Архитектура и интерфейс вызова
Скрипт должен быть реализован на языке Python 3 с использованием библиотеки `openpyxl`. Вызов осуществляется через командную строку (CLI) со следующими параметрами:

- `--url` (опционально, по умолчанию `http://127.0.0.1:5001`): адрес REST API сервиса управления задачами;
- `--date` (опционально, по умолчанию текущая дата системы `YYYY-MM-DD`): дата, относительно которой рассчитываются метрики просрочки и близости дедлайнов;
- `--output` (обязательный параметр): путь для сохранения результирующего Excel-файла.

Вывод скрипта в `stdout`: JSON-строка со сводными метриками (`total`, `completed`, `in_progress`, `completion_rate`, `overdue`, `overdue_active_rate`, `output`).

## 3. Требования к валидации и надежности
1. **Валидация целостности данных:**
   - Наличие всех обязательных ключей: `id`, `title`, `priority`, `due`, `done`.
   - Уникальность числовых идентификаторов `id`.
   - Допустимые значения приоритета: только `high`, `normal`, `low`.
   - Корректность даты дедлайна: формат `YYYY-MM-DD` или `null`.
2. **Безопасность (Formula Injection Prevention):**
   - Названия задач могут содержать произвольный пользовательский ввод (включая символы `=`, `+`, `-`, `@`). В ячейках Excel названия задач должны явно маркироваться строковым типом данных (`cell.data_type = "s"`), исключая исполнение формул в табличных процессорах.
3. **Защита от случайной перезаписи:**
   - При попытке записи в уже существующий файл скрипт должен выбрасывать исключение `FileExistsError` и прерывать выполнение.

## 4. Требования к структуре книги Excel

Книга должна содержать минимум два листа:

### Лист 1: «Реестр задач»
- Таблица с полным перечнем задач, отсортированных по возрастанию `id`.
- Столбцы:
  1. `ID` — уникальный номер задачи (числовой, выравнивание по центру).
  2. `Название задачи` — текст заголовка задачи (строковый, выравнивание по левому краю, ширина ~50 символов).
  3. `Приоритет` — русскоязычное наименование приоритета (`Высокий`, `Обычный`, `Низкий`).
  4. `Срок сдачи` — дедлайн задачи (`YYYY-MM-DD`) или значение `Без срока`.
  5. `Статус` — `Выполнено` либо `В работе`.
  6. `Просрочена` — индикатор просрочки: `Да`, `Нет` либо `—` (для задач без срока). Задача считается просроченной, если `done == False`, `due` задан и `due < дата_отчета`.
  7. `Дней до срока` — количество дней до дедлайна относительно даты отчёта (`+N`, `-N` или `—`).
- Визуальное оформление:
  - Шапка: темно-синий фон (`#1B365D`), белый жирный шрифт, закрепление верхней строки (`freeze_panes = "A2"`).
  - Включенный автофильтр по всей таблице (`auto_filter`).
  - Чередование цвета строк (зебра: белый / мягкий серый `#F7F9FB`).
  - Выделение просроченных статусов контрастным красным цветом.

### Лист 2: «Сводная аналитика»
- Структурированный управленческий дашборд, разделенный на три логических блока:
  1. **Блок KPI:**
     - Дата формирования отчёта.
     - Всего задач в системе.
     - Выполнено задач (Done).
     - В работе (Active).
     - Процент выполнения: `(Done / Total) * 100` (округление до 2 знаков).
     - Просрочено активных задач.
     - Доля просроченных среди активных задач (%).
  2. **Матрица распределения (Приоритет × Статус):**
     - Таблица по приоритетам (`Высокий`, `Обычный`, `Низкий`) с колонками: `Всего`, `Выполнено`, `В работе`, `Из них просрочено`.
     - Строка `ИТОГО` с двойным нижним подчеркиванием и суммированием.
  3. **Структура дедлайнов:**
     - Задач с установленным сроком.
     - Задач без срока.
     - Просрочено (критический скоуп).
     - Задач со сроком в течение ближайших 7 дней.

## 5. Требования к тестированию
Скрипт должен сопровождаться набором модульных тестов (`test_generate_report.py`), проверяющих:
- Корректность математических расчётов на тестовой выборке.
- Экранирование формул Excel.
- Работу с пустым списком задач.
- Обработку невалидных входных данных.
- Защиту от перезаписи существующих файлов.
